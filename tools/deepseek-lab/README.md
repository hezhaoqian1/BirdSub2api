# DeepSeek Lab — 私有渠道测试台

v1.2 增加 Railway 私有部署：密码登录、12 小时安全 Cookie、退出登录、全部历史/API/导出鉴权、持久卷和公网地址校验。没有密码或 HTTPS 域名配置时云端拒绝启动。

v1.1 实测修订：正确加法等式不再误判成数值错误，而是标记格式不符；运行时展示真实参数和最近12条可展开证据；首次响应前也保存任务以便刷新恢复；空闲读超时与总时限分开分类。可用 `python regrade.py 报告ID` 重评已结束报告，保留 report.original.json，不重新调用上游。

输入 URL + API Key → 获取模型 → 勾选模型 → 选择套件 → 开始 → 查看逐条证据和导出报告。

这是独立工具，不连接生产后台，不读取站内管理 token，不修改价格、路由、余额或配置。测试会对你选定的渠道发送实际 API 请求，按渠道规则产生用量。Key 仅在浏览器当前页面、运行进程与请求子进程的内存中使用；不写入配置、日志或报告，不放入 localStorage。进程结束后需重新输入。报告保存在本地，包含测试请求、正文、思考及 usage，分享前应检查业务内容。

## 启动与使用

需要 Python 3.10+。Windows 双击 start.cmd，或 PowerShell 执行 ./start.ps1。安装依赖后会打开 http://127.0.0.1:8767/。

手动运行：

    python -m pip install -r requirements.txt
    python app.py --open

端口占用时：python app.py --port 8768 --open

默认仅监听 127.0.0.1。云端设置 LAB_HOSTED=1 后监听 0.0.0.0:$PORT，必须按下述方式启用鉴权；不要使用无认证反向代理暴露本地模式。

## Railway 与历史/密钥边界

- 单服务、单副本，挂载 Railway 持久卷 `/data`，设置 `LAB_RESULTS_DIR=/data/results`。新测试历史写入持久卷，容器重新部署不删除历史；删除持久卷仍会丢失数据，重要报告请导出备份。
- 设置 `LAB_HOSTED=1`、`PORT=8080`、`LAB_PUBLIC_URL=https://你的域名`，以及 `LAB_PASSWORD_SHA256`（强随机访问密码的 SHA-256 小写十六进制摘要）。也支持 Railway 自动注入的 RAILWAY_PUBLIC_DOMAIN。
- 访问密码是管理测试台用的，与渠道 API Key 无关。一个密码对应共享管理空间；知道该密码的人可以看全部历史、发起/停止测试。没有用户间数据隔离，不宜向客户开放共享密码。
- 登录后使用 Secure、HttpOnly、SameSite=Strict Cookie；12 小时过期，重启撤销全部会话。连续错误登录限速；表单和 API 校验同源/CSRF。除无敏感数据的健康检查与登录页外，页面、报告和接口均要求登录。
- 渠道 API Key 从浏览器通过 HTTPS 发送到测试服务器，在内存中用于访问指定上游。不会保存渠道鉴权头，不放入 localStorage、不写请求日志；持久化前从配置、元数据、请求和返回内容中删除输入 Key 的原文回显。没有使用第三方埋点或前端外链资源。
- 这不是端到端加密或密钥保险库：浏览器、运行中的服务器和指定上游会接触 Key；Railway 项目管理员有控制运行环境的能力。上游 URL 使用 HTTP 时，该段链路仍是明文。人为把其他密钥/业务秘密放进请求正文，或上游以编码变体回显密钥，不能保证自动识别；历史/下载报告需要按敏感资料管理。
- 云端拒绝连接私网、环回、链路本地和元数据 IP；DNS 解析后固定已校验公网地址连接，保留原 HTTPS 主机名验证。关闭自动重定向，防止凭据被转发到另一地址。此限制不影响本地 mock 模式。
- 部署包只包含应用源码、静态页面及公开题库；本地 `results/`、`.runtime/`、密钥、日志均不上传。本地旧历史不会自动迁移。
- `railway up` 应在本目录操作，或通过 `--path-as-root` 上传经过检查的独立部署目录。`Dockerfile` 使用明确 COPY 清单；不要从仓库根上传业务配置。
- 修改密码摘要需要重启/重新部署以撤销旧会话。服务重启会中断正在运行的测试并保留已完成证据；不会自动重发计费请求。

1. 填写渠道名称、URL、Key，点击“获取模型”，勾选所需模型。
2. 可添加多个渠道，同一题集跨渠道对比。模型列表缺失或报错时可手填名称；列表存在不代表推理接口可用。
3. 根地址、/v1、完整 /v1/chat/completions 均可。自定义网关前缀填写完整 API 基地址，例如 /api/v1。/dashboard 会归一到 /v1。
4. 默认快速检查：每模型15次。完整测试：每模型51次。缓存专项：12次。重复轮次乘算总数，原始请求每轮额外1次。先预览可看到数量和输出预算上限；不是价格估算。
5. 不同渠道/模型可并发1–4，同一组合内顺序运行。默认请求空闲超时90秒、总墙钟超时240秒。可调上限；不能把不同超时设置下的成功率直接比较。
6. “停止”会终止本地请求子进程、停止后续测试并保存已完成记录。断开连接不保证上游停止计算或扣费。
7. 历史列表可查看和比较报告；参数/题集签名不同会提示不可直接排名。HTML为独立离线报告；JSON保留结构化证据。

命令行（不把密钥写进命令行历史）：

    python cli.py --url https://example.com --list-models
    python cli.py --url https://example.com/v1 --models deepseek-v4-pro,deepseek-v4.1-flash --suites speed,quality,reasoning,cache,community

运行后交互输入隐藏Key；也可以用 --key-env YOUR_ENV_NAME 指定已有环境变量名称。此参数接收变量名，不是密钥本身。

## 六类测试

### 速度与协议：3次

相同任务输出0至127的JSON数组。只用完整正确样本汇总速度，同时保留失败。分别测响应头、首个非空语义事件、首思考、首正文、正文结束、finish、请求总耗时。JSON非流式响应没有可测首字，不把总耗时冒充首字。

报告的 usage完成token/总时长 包含可能的思考token，是端到端观测值，不是模型纯生成TPS。短时间集中喷出正文会标记缓冲输出。三次样本的P95基本是最大值；若要评估尾延迟，应增加独立样本和时间窗口。

### 随机推理：8题

圆环独立座位、数字整除、固定点排列、条件概率、最小拖期、模幂、Python引用语义、真假话逻辑。前6题根据种子变化，本地枚举或精确算法计算标答；后2题固定。相同种子跨模型题目一致。多轮重复衡量一致性，不把重复题当作更多独立智力样本。

### 思考诊断：4次

同一日期题分别使用：enabled+high；disabled且无effort；disabled+max（刻意设置的冲突诊断）；enabled+128输出预算。前三项除思考参数外相同；第四项是预算压力实验。常规题选择“关闭”时不会自动附加effort，冲突只在专用诊断中保留。

检查：关闭仍返回思考、思考复制进正文、预算截断、无答案、超长思考配短答案、重复120字符块、正文结束后长时间等待。长短和重复率是筛查规则，不是语义裁判。需展开全文判断是否跑题、反复自检或存在逻辑错误；没有外露 reasoning 不代表模型没有推理。未提供思考字段真实性鉴定。

### 缓存：12次

A-cold → A-warm1 → A-warm2：完全相同请求，建立冷/暖观察。
B-tail1/2：保持长前缀，修改尾部查询，正确答案随之变化。
C-prefix1/2：修改最前端标记，其余数据保持不变。
D-new1/2：新的前缀和全部数据，正确答案变化。
A-restore：恢复原始请求。
E-thinking1/2：相同A数据，开启思考，用于观察参数与检索正确性关系。

每次运行、每个模型组合有独立前缀，减少跨渠道/别名预热串扰；同一组合重复轮次保留前缀，用于持续稳定性观察。首个请求仍不能保证绝对冷缓存。默认间隔3秒，构建可能是异步的；失败或未预热充分时，不断言缓存坏了。前缀由实际请求UTF-8 bytes的SHA256追踪。

预热摘要只统计A-warm1/2，不把改前缀、全新数据和暖缓存混为一个分数。同时展示“所有有统计的暖样本”和“完整答对的暖样本”，防止缓存高但答错/复读旧答案看起来很好。相同请求hash下输入token变化会标记，可能来自路由、模板、分词器或计数口径，单靠它不能证明偷换模型。

### 社区题：24道固定子集

BBH 12道（4类各3题）、MATH-500 8道、BBEH 4道，沿用我们此前实际测过的题目，以便复现。每题带来源和原始索引，题库及原文件hash保存在data/。标准答案只在本地评分，不发送给模型。没有下载或执行远程评测代码。

这不是完整官方评测：零样本提示、题目数量、输出预算、评分器都与正式榜单可能不同。公开旧题可能进入训练数据。MATH题中图形保留Asymptote源文本，不是原始图片输入。使用保守的答案抽取、有限有理数等价判断；未匹配数学表达标记“待复核”，不会擅自认为所有数学不匹配都是真错。BBEH使用本地保守末行匹配，并非上游完整评分器。选项C和(C)语义相同可给分，同时记录格式不一致。

### 原始请求复现

粘贴完整Chat Completions JSON。只替换所选model，不偷偷更改stream、max_tokens、thinking、reasoning_effort、tools等字段。无预期答案则标记人工评审，不给伪正确率。可观察工具调用但不自动执行工具；工具调用的多轮闭环不在本版范围。被截断的日志、只留首尾的请求不能称为完全复现。

## 指标口径与我们踩过的坑

1. 缓存字段缺失 ≠ 零。直接API保留null/缺失/冲突，无法得出比例时显示未知。多种字段不一致会报冲突，不取最大值美化。若库里已经把缺失写成0，则仅凭账单无法恢复差别。
2. 分母不能混用。OpenAI兼容prompt_tokens通常包含缓存；不能再加一次cache命中。Anthropic风格input_tokens另加cache_read和cache_creation。只有input_tokens而没有明确schema时不推定比例。站内账单input_tokens排除缓存，需用input+cache_read+cache_write作分母，这是另一个数据契约，本工具不直接导入账单。
3. 缓存率按token加权，不平均每条百分比。无流量/无输入无分母不是0%。只有1条样本不能据此排名。
4. 高缓存自报不是实际KV命中证明。延迟下降、同前缀重复、改数据后答对均是旁证；无法仅通过URL+Key审计供应商账单。不能据99%就宣布真或假。
5. 模型返回名不是身份。请求Pro返回0813、同名返回不同风格是路由线索，不是模型鉴定。按请求名和返回名都保留统计，不能只按别名合并。
6. 2026-10-16/17站内窗口曾观察：普通zzone Pro缓存71.69%，独立0813渠道仅3.43%；另一个0813渠道78.06%。它说明需要看具体渠道路径，不能推论“0813都差”。这些是历史现象，不是本工具硬编码的永久排名。
7. 缓存预热不能并发乱序。单一组合顺序执行，独立组合才并发。不同用户、前缀长度、请求组成和负载不同，生产统计不能替代同题对照。
8. 192曾出现同请求输入token漂移、disabled仍输出reasoning、正文等于思考、只思考无正文、算出答案后继续自检到预算耗尽。分别记录证据，不统称“降智”或“假模型”。
9. max_tokens可能同时覆盖思考与答案。8192全部用于思考会没有最终答案；128低预算诊断失败不能直接算模型能力差。质量榜只计实际交付正确，失败原因独立呈现。
10. disabled+reasoning_effort=max可能触发不一致行为。原始请求复现保留冲突，但常规关闭测试去掉effort；参数改变同时返回模型名变化时，不归因于单个参数。
11. 思考不是越长越好，越短也不等于缩水。简单日期题曾消耗8108个思考token；复杂题也可能很快正确。必须联合答案、任务难度、用量与全文分析。
12. HTTP200不等于成功。正文为空、length截断、响应体error、流协议坏帧都单独记录。finish=stop但缺少[DONE]作为兼容警告；工具调用不是普通文本答案。
13. 思考里的正确答案不算已交付。计分只看content，正文复制思考也不计完整正确交付。语义正确与格式合规分开。
14. 首思考和首正文不是同一指标。非流式JSON没有TTFT；服务端或客户端缓冲会导致假“超高TPS”。本地SSE逐字节读取减少512B缓冲影响，但仍不能分离网络/服务端排队与推理时间。
15. 曾发生正文约6秒完成、finish/usage约50秒才到。单独记录tail_s，不只展示正文速度忽视用户等待。
16. 60秒超时失败、180秒重跑成功，不能说第一次智力差。重跑也可能发生在不同负载和并发下。无自动重试、每次运行独立保存失败，鉴权/余额错误立即熔断，连续三次传输/HTTP失败停止该组合。
17. 标答也需审查：歧义选项、括号、等价分数、图形输入缺失会制造假失败。自动评测不是免复核的智力证明。
18. 所有时间都是客户端观测，usage是上游自报，无法证明真实收费。没有官方参考Key时，不做“与官方一致”的声明。速度排名只针对同样请求、同预算、同思考设置的样本。
19. 小样本准确率、重复轮次不构成完整能力榜。报告保留不同题目数和描述性区间，不制造一个混合智力/速度/缓存的总分。
20. 原始请求和模型输出都是不可信内容。网页仅以文本展示，不执行返回HTML、代码或工具；远程响应限制8MB，事件日志最多4000帧，超限明确标记。Key脱敏覆盖完整响应对象，不跟随重定向转发凭据。

## 文件与验证

app.py：本地HTTP服务，Host/Origin校验和每次启动会话token。
transport.py：独立进程采集器，SSE/JSON、硬超时、取消、usage归一化。
suites.py：固定/随机题、缓存对照、标答与异常检测。

static/：中文界面、历史对比、离线报告渲染。
data/：24题固定子集、来源hash、第三方归属说明。
tests/：本地模拟上游，覆盖缓存缺失/冲突、缓冲、截断、错误、取消、参数保留等。

results/会保存报告，不纳入Git；复制整个目录即可迁移工具。删除报告请在工具关闭后自行清理对应results子目录。修改题库/评分器应增加版本号再比较历史。

## v1.1 实测后改进

- 正确的加法等式与纯整数输出分开判定语义和格式，避免把算对误报为能力错误。
- 停在 FINAL 标记、未闭合 boxed 答案也会提示异常，不能仅凭 finish=stop 判断实际交付完整。
- 结束后可逐条人工复核；保存理由、原评分和审计日志。只看到思考中答案正确不能补算成功。
- 运行中可查看最近12条完整证据，展开时暂停自动重绘。运行参数始终显示，刷新不会丢失任务。
- 大报告先载入摘要和请求目录，再按需读取单条证据；下载的 JSON/HTML 仍保留完整证据，可能较大。
- 连接超时、读取空闲超时、墙钟超时分别记录；HTTP错误不再重复计成多个无正文/流式格式异常。
- 同端口重复启动失败不会修改正在运行的报告。
- 历史重新判分：`python regrade.py 报告ID`。不发模型请求，保留 report.original.json 和 grading-changes.json；已有人工复核结论会保留；重判不追加或覆盖人工审计记录。


### 真实渠道回归中新遇到的情况

- `finish=stop` 也可能停在 `FINAL:`、`The answer is:` 或未闭合的 `\boxed{`，不能把 stop 等同于用户收到完整答案。
- 正文已经明确给出正确答案、但末尾格式损坏时，可人工确认语义正确，同时必须保留格式异常；只有思考里答对不能这样补分。
- 有渠道把两条完整 JSON 的 data 行放进同一个 SSE 事件，缺少空行分隔；严格 SSE 解析会得到无法解析的拼接 JSON。网页显示错误片段和答案，区分语义答对与协议合规交付。
- 重复请求自报缓存接近100%，也可能在长表取数上连续答错。选择渠道时必须一起看正确性、缓存、异常和速度。
- 命中与未命中加总可能与总输入差1个或更多token。工具提示口径差异并保留上游原值，不据此直接断言伪造。
- 大批量原始流日志可达百MB级。运行中逐条增量写入，摘要与单条证据按需读取；结束时才生成全量导出。中断后根据已保存的请求编号恢复。

- Windows读取文件与原子替换竞争可能抛出PermissionError；保存加入有上限的重试。并发任务用完成顺序收集异常，避免后面的线程已失败却继续显示为运行中。
