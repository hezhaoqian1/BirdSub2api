# 上游余额查询

账号管理中，桌面表格通过独立的「余额」列显示查询结果，窄屏时显示在账号名旁。每条配置了 Base URL 的 API Key 账号自动查询；列设置中可隐藏余额列。点击金额或齿轮查看详情和配置，旁边的刷新图标刷新单条结果；更新时间、共享来源和错误详情收在提示及弹窗中。新增和导入无需增加必填字段：打开列表时自动识别 Sub2API / New API；缓存 5 分钟，页面可见时定期更新。可单条刷新或刷新本页。手动刷新最低间隔 30 秒。当前没有离线定时监控或自动停用账号行为。

## 查询方式

| 方式 | 接口 | 凭据 | 展示含义 |
| --- | --- | --- | --- |
| Sub2API | `GET /v1/usage` | 账号现有 API Key | 依据响应区分钱包、密钥额度、订阅额度 |
| New API 自动 / 令牌 | `GET /api/usage/token/` | 账号现有 API Key | 优先使用 `data.user_quota`；否则仅为令牌额度 |
| New API 账户 | `GET /api/user/self` | 访问令牌及 `New-Api-User` 用户 ID | 账户余额 `data.quota` |

兼容 New API 的 `success: true` 和 ZZONE 等站点的 `code: true` 响应格式。New API 的“令牌不限额”不能推出真实钱包余额。无限令牌可能返回负的 `total_available`，本功能不会把它作为账户欠费或无限余额。较新的 New API 可在令牌设置中开启用户额度查询，是否可用由上游版本和配置决定。

配置 New API 账户查询时，在上游“安全与访问 → 访问令牌”（部分版本在个人设置）创建具有读取自己账户权限的令牌；填写上游数字用户 ID。保存访问令牌要求服务器设置固定 `TOTP_ENCRYPTION_KEY`。已有令牌不回显，留空保留；切换其他查询方式会清除已保存的访问令牌。

New API 通过不带认证的 `/api/status` 读取 `quota_per_unit`。站点声明 USD 时用原始配额除以该参数；声明 CNY 时还乘以站点公布的正数 `usd_exchange_rate`，显示人民币金额。缺少有效换算参数或币种不支持时保留原始 `QUOTA`，不猜测汇率或套用固定的 500000。余额金额统一显示两位小数，快照保留换算后的精度。

## 共享钱包

先为一个账号成功查到**账户余额**，再在其他账号的余额配置中选择“共用另一个账号的钱包”，填写来源账号在本站的 ID，并确认属于同一个实际钱包。要求上游根地址一致，不允许关联链、环或共享令牌额度。关联账号共用来源账号的结果及刷新冷却，不重复统计金额。

修改账号的 API Key 或地址会使旧配置、快照失效，避免继续展示其他钱包的余额。来源账号删除、改地址、改为令牌额度时，会提示重新配置。查询失败保留最后成功值与时间，不修改本地配额、账号健康状态或调度开关。

## 实现与维护

- 迁移 `248_upstream_balance_accounts.sql` 保存独立的查询配置和快照；访问令牌加密存储。账号普通 JSON 导入/导出不包含这些配置。
- 查询只发往账号配置的上游地址，遵守现有出站 URL 策略及账号代理，并禁止携带凭据跟随重定向。单账号超时 15 秒，响应上限 128 KiB，每个服务实例的整条查询路径并发最多 4（含数据库读取）；刷新每批最多 10 条。
- `POST /api/v1/admin/accounts/upstream-balances/query` 获取缓存或刷新；`PUT /api/v1/admin/accounts/:id/upstream-balance` 保存配置。两者仅管理员可用；配置请求体不写入审计日志。
- 迁移 `249_upstream_balance_refresh_lease.sql` 添加查询租约：只在短事务中领取任务，等待上游时不占数据库连接或行锁。同一实例合并同钱包的并发请求；其他实例遇到有效租约直接读取缓存。任务取消会释放租约，进程异常退出后租约在 30 秒过期。保存配置会使进行中的旧查询失效，迟到的响应不能覆盖新配置。
- 余额查询使用独立 HTTP 客户端缓存，不复用或淘汰模型调用连接。缓存最多 16 个客户端，空闲连接 30 秒释放；代理和出站安全策略沿用网关实现。它仍会消耗少量 CPU、网络及短时数据库资源，不代表零开销。
- 页面隐藏或离开时取消正在进行的余额请求；恢复显示时按缓存时间决定是否刷新。共享关联编辑串行校验，禁止循环关联。
- 本地回归覆盖了：模型流式响应保持打开时余额请求能完成、余额缓存淘汰不影响网关连接、单数据库连接在上游等待期间可执行其他查询、多个批次的数据库读取并发不超过 4、旧租约结果不能覆盖新配置。未对生产环境做负载测试。

查询接口和字段映射参考并改写自 [CC Switch 的 UsageScriptModal.tsx](https://github.com/farion1231/cc-switch/blob/main/src/components/UsageScriptModal.tsx)，在 Go 中实现固定适配器，没有引入任意 JavaScript 执行。上游 MIT 许可及版权声明保存在 [cc-switch.txt](licenses/cc-switch.txt)。

本地 PostgreSQL 集成验证：设置 `TEST_POSTGRES_DSN` 后运行 `go test -tags=integration ./internal/service -run TestUpstreamBalancePostgresLeaseAndSharedWallet`。测试创建并清理独立 schema，覆盖单连接池下的租约释放、共享钱包冷却和配置失效；未配置 DSN 时跳过。
