# 企业微信告警

安全告警和运营告警推送到同一个企业微信群机器人，消息是纯文本。安全类消息标题为「安全告警」，渠道和用户余额类消息标题为「运营告警」，两类不会拼在同一条消息里。配置在「设置 → 安全 → 企业微信告警」，也可以用 `GET/PUT /api/v1/admin/security-alerts/config` 修改（PUT 为部分更新，需要二次验证）。每次修改配置都会往群里发一条变更通知。

## 运营告警

| 告警 | 触发条件 | 默认值 | 去重 |
| --- | --- | --- | --- |
| 渠道大额消费 | 渠道（上游账号）近 1 小时成本 ≥ 下限，且 ≥ 该渠道过去 7 天单小时 P95 × 倍数；7 天内没有消费的新渠道只看下限 | 下限 $100，倍数 3 | 同一渠道 3 小时一次 |
| 渠道余额预计很快用完 | 按近 3 小时余额下降速度估算，预计在 N 小时内用完 | 6 小时 | 每个级别一次，充值后重新监控 |
| 渠道余额不足 | 余额低于提醒线（按上游返回的币种比较） | USD 20 / CNY 100 | 同上 |
| 渠道余额已用完 | 余额 ≤ 0 | — | 同上 |
| 渠道因额度不足已停用 | 账号被置为错误状态，报错包含「额度不足 / 余额不足 / insufficient / quota / balance / credit」等 | 开启 | 按报错内容去重 |
| 关注用户余额低于提醒线 / 已用完 | 管理员指定的用户余额低于各自的提醒线，或 ≤ 0 | 名单为空 | 每个级别一次，充值回到提醒线以上后重新监控 |
| 渠道监控连续失败 / 已恢复 | 渠道监控（V1 主动探测）主模型连续 3 次检测失败；之后第一次检测成功时推送恢复 | 开启 | 每轮故障一条告警、一条恢复，多实例共用一条记录 |

- 成本口径与利润统计一致：`COALESCE(account_stats_cost, total_cost) × account_rate_multiplier`。订阅制账号（OAuth / Setup Token）不参与大额消费判定。
- 余额检查每 10 分钟由一个实例执行（`channel_balance_check_minutes`，0 关闭，最小 5），只刷新参与调度、配置了 Base URL 的 API Key 账号，同时最多占用余额查询 4 个并发名额中的 2 个。关闭了余额查询的账号跳过；从未查询成功的账号失败后 6 小时内不再重试。
- 共用同一个钱包的多个账号（同一上游、余额相差不到 1%）合并成一条消息。
- 「预计很快用完」需要至少 30 分钟的余额样本，部署后第一次检查不会触发。充值造成的余额上涨不计入扣费速度。
- 状态保存在 `security_alert_state`（每个账号/用户当前已推送的级别和当时的余额），余额样本保存在 `security_alert_balance_samples`，保留 2 天。级别只升不降，直到检测到余额比上次记录高（视为充值）。
- 查不到余额的渠道（令牌不限额、接口 404 等）只能靠大额消费和「额度不足已停用」两条规则发现问题。
- 渠道监控告警以前推送到钉钉机器人，现在和其他运营告警用同一个企业微信机器人，钉钉配置已删除。每个实例各自跑检测、各自计连续失败次数；先达到 3 次的实例在 `security_alert_state` 写入 `channel_monitor:<监控 ID>` 并推送，其他实例看到记录就不再推送；任一实例检测成功时删除记录并推送恢复（附告警时间和持续时长）。实例重启后第一次检测成功会核对一次记录，重启期间恢复的故障也会补发恢复通知。停用或删除监控会清掉记录。告警关闭时不推送也不写记录，恢复时只清记录。

## 日报

每天 9 点（北京时间）的日报额外包含：昨日渠道成本和最高的 3 个渠道、当前处于余额告警中的渠道、关注用户中低于提醒线的人数。

## 配置字段

| 字段 | 说明 |
| --- | --- |
| `channel_spend_floor` | 渠道近 1 小时成本下限（$），0 关闭大额消费告警 |
| `channel_spend_multiplier` | 超过 7 天单小时 P95 的倍数 |
| `channel_balance_check_minutes` | 余额检查间隔（分钟），0 关闭余额告警 |
| `channel_low_balance_usd` / `channel_low_balance_cny` | 余额提醒线，0 表示不按金额提醒 |
| `channel_runway_hours` | 预计用完提前提醒的小时数，0 关闭 |
| `channel_quota_error_notify` | 额度不足停用时是否提醒 |
| `channel_monitor_notify` | 渠道监控连续失败 / 恢复时是否提醒 |
| `user_balance_watches` | `[{"user_id": 12, "threshold": 50, "note": "备注"}]`，最多 200 人，整表替换 |

## 单个用户的余额监控

用户管理页每个用户的余额旁边有「监控」按钮（操作菜单里也有「余额监控」），可以直接设置这个用户的提醒线和备注，或取消监控。按钮显示提醒线金额表示已在监控，橙色表示当前余额已低于提醒线。它只改名单里这一个用户，不会覆盖其他配置，也不需要二次验证。

- `GET /api/v1/admin/security-alerts/user-watches`：名单，以及告警开关和机器人是否已配置
- `PUT /api/v1/admin/security-alerts/user-watches/:user_id`，body `{"threshold": 100, "note": "备注"}`：新增或修改（提醒线按分取整，需大于 0）
- `DELETE /api/v1/admin/security-alerts/user-watches/:user_id`：取消监控

新增、修改、取消都会往群里发一条「运营告警」通知。修改提醒线后该用户的告警状态会清零，如果余额已低于新提醒线，约 1 分钟内推送一次；只改备注不会重新推送。
